# Как писать новый регламент

Регламенты для CRM собираются **из исходного текста** `Регламент - АКТУАЛЬНЫЙ.txt` и заливаются через админку двумя артефактами: HTML-тело и файл вопросов теста.

Папка `регламенты/` — рабочее место для черновиков и примеров. В прод уходит содержимое, которое копируется в админку (тело + тест + название + описание).

---

## Источник истины

1. Открыть `Регламент - АКТУАЛЬНЫЙ.txt`.
2. Выбрать **один смысловой блок** (раздел / подраздел) — не мешать несколько тем в один регламент.
3. Перенести смысл **без искажений**: цифры, тайминги, формулировки скриптов, статусы CRM, штрафы.
4. Можно слегка подчистить орфографию и разбивку на списки — смысл менять нельзя.

Примеры соответствия блок → регламент:

| Блок в актуальном файле | Тема в админке |
|-------------------------|----------------|
| Вводная информация (звонки) | Регламент звонков менеджеров (вводная информация) |
| Налаживание контакта + выявление потребности | Контакт и потребность |
| Название цены | Название цены клиенту |
| Переписки в мессенджерах | Переписки в мессенджерах |
| Приоритеты | Регламент звонков менеджеров (приоритеты обработки заявок) |
| Обработка возражений | Обработка возражений |
| Заполнение CRM | Заполнение информации в CRM |

---

## Два файла на один регламент

Именование (пример для приоритетов):

```
reglament-8-priorities-body.html
reglament-8-priorities-test-questions.txt
```

Правила имён:

- префикс `reglament-`;
- по возможности номер раздела / id в CRM (`8`);
- короткий slug темы латиницей (`priorities`, `messengers`, `crm-fill`);
- суффикс `-body.html` для вёрстки;
- суффикс `-test-questions.txt` для теста.

Картинки (если есть) класть в `photo/` локально; в HTML указывать путь уже после загрузки в админку, например:

`/uploads/reglaments/content/reglament-….webp`

## 1. HTML-тело (`*-body.html`)

Копируется в поле «Содержание» регламента в админке.

### Обязательная обёртка

```html
<div class="reglament-article">
  …
</div>
```

### Классы

| Класс | Зачем |
|-------|--------|
| `reglament-subtitle` | Заголовок блока / секции |
| `reglament-list reglament-list--alpha` | Верхний список (a, b, c…) |
| `reglament-list reglament-list--roman` | Вложенный список (i, ii, iii…) |
| `reglament-list__section` | Пункт, у которого есть свой подзаголовок и вложенный список |
| `reglament-highlight` | Ключевая цифра / фраза / статус |
| `reglament-emphasis` | Важный акцент (тайминг, термин) |
| `reglament-figure` + `reglament-figure__img` | Картинка с `loading="lazy"` |

### Структура

1. Короткий подзаголовок темы.
2. При необходимости — вводный абзац (зачем правило).
3. Список секций по пунктам из актуального файла.
4. Скрипты клиенту — в `reglament-highlight` / кавычках, как в источнике.
5. Не выдумывать правила, которых нет в `Регламент - АКТУАЛЬНЫЙ.txt`.

Ориентир по разметке: `reglament-8-priorities-body.html`, `reglament-messengers-body.html`, `reglament-5-body.html`.

## 2. Файл вопросов (`*-test-questions.txt`)

Сверху **обязательно** указать то, что уйдёт в карточку регламента в админке: **название** и **описание**.

### Шаблон шапки

```
Название: Регламент звонков менеджеров (вводная информация)
Описание: Базовые правила работы диспетчера со звонками: сроки обработки заявок, Novofon, качество связи, манера общения, активное слушание и инициативность.

РЕГЛАМЕНТ id=N — «Краткое имя»
Файл: reglament-…-body.html
Тест: X вопросов
================================================================================

РЕКОМЕНДАЦИЯ ПО ПОРОГУ
----------------------
Вопросов: X
Порог прохождения: Y из X (≈Z%)
```

### Как писать название

- Формат: `Регламент звонков менеджеров (…тема…)` — общая серия в названии, уточнение темы в скобках.
- Пример: `Регламент звонков менеджеров (приоритеты обработки заявок)`.
- Не копировать сырой номер из txt («8. Приоритеты») — писать нормальное название темы.

### Как писать описание

- 1–2 предложения.
- О чём блок и зачем его читать / сдавать тест.
- Перечислить ключевые темы через запятую или двоеточие.
- Без воды и без копипасты всего раздела.

Пример для приоритетов:

```
Название: Регламент звонков менеджеров (приоритеты обработки заявок)
Описание: Порядок работы диспетчера: входящие звонки, переписки, просроченные, думающие и оценка качества — строго по приоритетам, с таймингами и правилами спасения чужих просроченных заказов.
```

### Вопросы

1. Только по тексту **этого** body — не смешивать темы соседних разделов.
2. Типы как в существующих тестах:
   - `один верный из четырёх` → `single_choice` + `correctIndex`;
   - `несколько верных` → `multi_choice` + `correctIndices`.
3. Порог обычно ≈80% (округлить вверх).
4. В конце файла — **краткая сводка** и блоки **PHP-массив** + **JSON** для «Импорт из JSON» в админке (как в `reglament-price-offer-test-questions.txt` / `reglament-8-priorities-test-questions.txt`).

---

## Чеклист перед заливкой в админку

1. [ ] Блок взят из `Регламент - АКТУАЛЬНЫЙ.txt`, смысл сверен.
2. [ ] Есть `*-body.html` с классами `reglament-*`.
3. [ ] Есть `*-test-questions.txt`.
4. [ ] В шапке теста заполнены **Название** и **Описание**.
5. [ ] Вопросы покрывают ключевые цифры и запреты/обязательства раздела.
6. [ ] В импорте PHP/JSON индексы ответов совпадают с пометками «← ВЕРНЫЙ».
7. [ ] В админке: создать/открыть регламент → вставить название, описание, HTML-тело → импортировать вопросы → выставить порог.

---

## Чего не делать

- Не писать регламент «из головы», если пункта нет в актуальном txt.
- Не класть несколько крупных разделов в один body «на будущее».
- Не забывать название и описание в файле вопросов — без них карточку в админке всё равно придётся заполнять вручную, и легко ошибиться формулировкой.
- Не коммитить секреты / доступы к CRM в эту папку.
