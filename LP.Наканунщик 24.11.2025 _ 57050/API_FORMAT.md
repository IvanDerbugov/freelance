# Формат API для чата AI-ассистента "Наканунщик"

## Endpoint
```
POST https://amp.kinetica.su/clientservices/kinetica/bot/
```

## Формат запроса (Request)

### Headers
```
Content-Type: application/json
```

### Body
```json
{
  "messages": [
    {
      "role": "bot",
      "content": "Добрый день! Я Наканунщик из KINETICA. Рад помочь вам с идеями для спецпроекта. Расскажите, пожалуйста, чем занимается ваш бизнес?"
    },
    {
      "role": "user",
      "content": "У нас e-commerce-бренд в сфере товаров для дома и уюта. Продаём через собственный сайт и маркетплейсы: текстиль, декор и небольшую мебель для квартир и загородных домов."
    },
    {
      "role": "bot",
      "content": "Отличная ниша! Товары для дома и уюта всегда актуальны, особенно с фокусом на современный дизайн и быструю доставку. Чтобы я мог предложить наиболее релевантные идеи спецпроектов, подскажите, пожалуйста, какая основная цель сейчас стоит перед вашим брендом?"
    },
    {
      "role": "user",
      "content": "Сейчас для нас приоритет — привлечение новых клиентов (лиды)."
    }
  ]
}
```

### Поля запроса:
- **messages** (array, обязательное) - Массив всех сообщений в чате (полная история диалога)
  - **role** (string, обязательное) - Роль отправителя: `"bot"` для сообщений бота, `"user"` для сообщений пользователя
  - **content** (string, обязательное) - Текст сообщения

---

## Формат ответа (Response)

### Успешный ответ (200 OK)

API может вернуть ответ в одном из следующих форматов:

#### Вариант 1: Массив сообщений
```json
[
  {
    "role": "bot",
    "content": "Отлично, теперь, когда мы знаем, что ваша цель — привлечение лидов, а тональность — уютная и домашняя, но современная, я готов предложить несколько идей спецпроектов..."
  }
]
```

#### Вариант 2: Объект с полем content
```json
{
  "content": "Отлично, теперь, когда мы знаем, что ваша цель — привлечение лидов..."
}
```

#### Вариант 3: Объект с role и content
```json
{
  "role": "bot",
  "content": "Отлично, теперь, когда мы знаем, что ваша цель — привлечение лидов..."
}
```

#### Вариант 4: Объект с reply_to_user (основной формат API)
```json
{
  "reply_to_user": "Отлично, теперь, когда мы знаем, что ваша цель — привлечение лидов...",
  "options": [],
  "debug_error": ""
}
```

**Примечание:** Если `debug_error` содержит код ошибки (например, "429"), это означает проблему на стороне сервера (rate limit, ошибка AI и т.д.). В этом случае `reply_to_user` содержит сообщение об ошибке.

#### Вариант 5: Просто строка
```json
"Отлично, теперь, когда мы знаем, что ваша цель — привлечение лидов..."
```

### Обработка ответа на фронтенде:
- Если вернулся массив — берется последнее сообщение с `role: "bot"`
- Если вернулся объект с `reply_to_user` — используется `reply_to_user` как текст ответа бота (с обработкой ошибок типа 429)
- Если вернулся объект с `content` — используется как текст ответа бота
- Если вернулся объект с `role` и `content` — используется как есть
- Если вернулась строка — используется как текст ответа бота

### Ошибка (400/500)

При ошибке API вернет соответствующий HTTP статус код. Фронтенд обрабатывает ошибки и показывает пользователю сообщение об ошибке.

## Примеры использования

### Пример 1: Первое сообщение пользователя
**Request:**
```json
{
  "messages": [
    {
      "role": "bot",
      "content": "Добрый день! Я Наканунщик из KINETICA. Рад помочь вам с идеями для спецпроекта. Расскажите, пожалуйста, чем занимается ваш бизнес?"
    },
    {
      "role": "user",
      "content": "У нас интернет-магазин одежды"
    }
  ]
}
```

**Response:**
```json
{
  "role": "bot",
  "content": "Отличная ниша! Интернет-магазин одежды — это интересная сфера. Чтобы я мог предложить наиболее релевантные идеи спецпроектов, подскажите, пожалуйста, какая основная цель сейчас стоит перед вашим брендом?"
}
```

### Пример 2: Пользователь указал цель
**Request:**
```json
{
  "messages": [
    {
      "role": "bot",
      "content": "Добрый день! Я Наканунщик из KINETICA. Рад помочь вам с идеями для спецпроекта. Расскажите, пожалуйста, чем занимается ваш бизнес?"
    },
    {
      "role": "user",
      "content": "У нас интернет-магазин одежды"
    },
    {
      "role": "bot",
      "content": "Отличная ниша! Интернет-магазин одежды — это интересная сфера. Чтобы я мог предложить наиболее релевантные идеи спецпроектов, подскажите, пожалуйста, какая основная цель сейчас стоит перед вашим брендом?"
    },
    {
      "role": "user",
      "content": "Сейчас для нас приоритет — привлечение новых клиентов (лиды)."
    }
  ]
}
```

**Response:**
```json
{
  "role": "bot",
  "content": "Отлично, привлечение лидов — это понятная и важная цель! Чтобы идеи спецпроектов максимально точно попали в вашу аудиторию и бренд, расскажите, пожалуйста, какую тональность вы бы хотели передать в проекте?"
}
```

## Примечания

1. **История сообщений**: В запросе всегда отправляется полная история диалога (все предыдущие сообщения + новое сообщение пользователя). Бэкенд использует всю историю для генерации контекстного ответа.

2. **Управление диалогом**: Бэкенд сам управляет логикой диалога на основе истории сообщений. Фронтенд не передает информацию о шагах или состоянии диалога.

3. **Формат ответа**: API может вернуть ответ в разных форматах (массив, объект, строка). Фронтенд обрабатывает все варианты и извлекает текст ответа бота.

4. **Индикатор загрузки**: Фронтенд показывает индикатор загрузки (анимированные точки) во время ожидания ответа от API.

5. **Обработка ошибок**: При ошибке API (сетевые проблемы, HTTP ошибки) фронтенд показывает пользователю понятное сообщение об ошибке и предлагает попробовать еще раз.

6. **Сохранение состояния**: Фронтенд сохраняет историю чата в localStorage, чтобы при обновлении страницы диалог не терялся.

7. **Первое сообщение**: При первом заходе на страницу показывается приветственное сообщение от бота: "Добрый день! Я Наканунщик из KINETICA. Рад помочь вам с идеями для спецпроекта. Расскажите, пожалуйста, чем занимается ваш бизнес?"
